- **更新日期**：2026-09-14

## 1. 痛点场景深度拆解

针对高校毕业设计场景以及使用现有大模型/传统 `docx` 库编写论文的核心问题：

1. **高校“陈年老模板”排版断裂与静态页丢失**：
   - 绝大多数高校下发陈年 `.docx` 模板，内部前置有固定的**封面、开题报告表、独创性声明、指导教师评阅表、答辩记录表**等。这些页面通常包含特定表格排版、下划线、印章占位符，**必须 100% 原样保留，不可重新排版或丢失**。
   - 模板正文中混杂着指导说明（如“*此处为宋体小四号，行间距1.5倍，首行缩进2字符，正文不少于10000字*”），传统生成方式无法区分“哪些是必须原样保留的骨架”、“哪些是格式说明指令（需提取规则后删除）”、“哪些是真正的内容填充区”。
2. **Word 高级学术排版能力缺失（角标与原生交叉引用）**：
   - 传统脚本或 AI 插件生成的文本，通常只是打出普通文字 `[1]` 或 `见图1-1`。在 Word 中不是真正的**上标（Superscript）**与**动态交叉引用（Cross-Reference）**。
   - 真正的 Word 交叉引用依赖底层 XML 的书签（Bookmark）与域代码（Field Code `REF` / `PAGEREF`）。没有原生引用，学生只要微调插入一张新图，后面所有的“图2-1”、“图3-5”以及参考文献编号就会全部脱节。
3. **多轮修改与审阅“前言不搭后语”（上下文断层与矛盾）**：
   - 导师提出修改意见（例如“把单体架构改成微服务架构”或“在第三章补充用户权限与审核业务流”）。
   - 用户另开对话或进行局部提示词修改时，AI 缺乏全局状态记忆，修改了局部导致前后文术语冲突、角色混乱、代码与需求不一致。
4. **过程文件杂乱无章与修改不可追溯**：
   - 多轮对话和反复修改在文件夹内制造了大量 `论文_最终版_修改1_copy(2).docx`，不仅没有版本控制链条，学生也不知道本次修改具体改动了哪些段落（缺乏语义 Diff 对比），无法安全回滚历史。
5. **本科毕业论文内容要素单一（“太水”、“缺图缺表缺界面”）**：
   - 普通本科毕业设计（尤其是计算机软开类、经管实证类）导师最看重的是工作量和真实感：必须有规范的三线表、系统架构图、数据流/业务时序图、E-R 图，甚至**真实可信的系统前端 UI 界面截图与原型图**。纯文字论文极易被判定为“假大空”。

## 2. 产品定位与核心价值

- **定位**：面向中国普通本科毕业生的**高合规、图文并茂、工程化版本可溯的毕业论文智能生成与审改工作流引擎**。
- **三大核心价值**：
  1. **零格式翻车（Format-First）**：底层精准解析老旧模板，静态页原样保留，正文样式由模板规则驱动；原生实现 Word 书签、交叉引用、上标角标、规范三线表。
  2. **高保真论文要素（Rich-Artifacts）**：自动生成架构图、流程时序图、E-R 数据图、甚至真实前端 UI 原型截图，使毕业设计看起来具备充足工作量。
  3. **像 Git 一样严谨的版本管理（Version-Traceable）**：消除凌乱中间文件，支持根据导师 Word 批注/修订/文本意见进行受控的连贯性重写，自动输出变更报告（Changelog & Diff）。

## 3. 底层排版与关键技术实现方案

### 4.1 陈年模板静态保留与样式解析方案
- **双轨剥离（Dual-track Decoupling）**：
  - 模板被加载时，利用 `lxml` 遍历 `word/document.xml` 的段落与节（`w:sectPr`）。
  - **静态判定规则**：通过关键词指纹库（“独创性声明”、“版权使用授权书”、“指导教师评阅书”、“答辩委员会决议”等）及特定非正文表格特征，将静态页的底层 XML 片段直接持久化为独立块（Blocks），保留所有原始样式、间距与下划线。
  - **样式规则提取器**：遍历 `word/styles.xml`，读取用户学校模板中配置好的内置样式属性（包括但不限于：`Heading 1`、`Heading 2`、`Normal`、`Caption` 等的字体、中文字符字号、段前段后磅值、行距倍数）。
  - **说明文字清洗**：根据启发式规则与大模型辅助，剔除正文中“*注：此处请填写……字号为小四宋体*”等模板说明文字，换为干净的内容挂载点。

### 4.2 Word 原生学术交叉引用与角标技术规范
- **真·交叉引用实现机制**：
  - 图题注标准 XML 格式：
    ```xml
    <w:p>
      <w:bookmarkStart w:id="101" w:name="_Ref_Fig_3_1"/>
      <w:r><w:t>图 3-1 系统总体架构图</w:t></w:r>
      <w:bookmarkEnd w:id="101"/>
    </w:p>
    ```
  - 正文引用点标准 XML 格式：
    ```xml
    <w:fldSimple w:instr=" REF _Ref_Fig_3_1 \h ">
      <w:r><w:t>图 3-1</w:t></w:r>
    </w:fldSimple>
    ```
  - 确保文档在 Word 中具有原生超链接高亮、Ctrl+点击跳转、F9 整体刷新序号的能力。
- **真·角标规范**：
  - 引用文献标注必须采用原生 `<w:vertAlign w:val="superscript"/>`，并且文本与文末参考文献顺序严格一致。
- **中国规范三线表（Three-line Table）**：
  - 顶线与底线采用 1.5pt（`w:sz="12"`）黑单线，栏目线（表头下）采用 0.75pt（`w:sz="6"`）单线，表内无竖线，表体行无横线。

## 4. 项目工作区与防杂乱版本管理体系

为了彻底根治“每次修改都在文件夹拉出一堆临时中间文档，无法追溯”的痛点，系统设立标准工作区规范：

```
paper_project_workspace/
│
├── project.json                   # 核心元数据：选题、专业、技术栈、全局实体字典
│
├── template/                      # 模板资产区
│   ├── raw_template.docx          # 原始学校模板文件
│   ├── static_blocks.xml          # 剥离出的免责声明、评阅表等静态段落
│   └── extracted_styles.json      # 提取的字体字号行间距排版规则
│
├── assets/                        # 生成的多模态资产区（永久管理）
│   ├── diagrams/                  # Mermaid 源码(.mmd) 与渲染图(.png)
│   ├── ui_mockups/                # 系统前端界面原型代码与高清截图
│   └── tables/                    # 数据字典、测试用例等结构化数据
│
├── .repo/                         # 内部轻量级版本控制存储（类 Git 机制）
│   ├── commit_001_v1.0_draft/     # 初稿快照（状态树、分章文本、引文图表索引）
│   └── commit_002_v1.1_edit/      # 针对导师批注的修改增量快照
│
└── output/                        # 面向用户的整洁交付区（永远保持清晰规整）
    ├── 20260915_毕业论文_v1.0_初稿.docx
    ├── 20260916_毕业论文_v1.1_批注修改版.docx
    └── 变更对比报告_v1.0_to_v1.1.md # 语义级改动清单（改了哪里、如何响应批注）
```

## 5. 后续迭代规划（Milestones）

1. **阶段 1：PRD 确认与核心数据结构设计**（当前）
   - 确定需求范围与技术路线，制定状态机与数据流结构。
2. **阶段 2：Word 底层排版引擎研发（Kernel）**
   - 实现模板双轨切分（静态保留/样式提取）、原生交叉引用书签注入、真角标、标准三线表。
3. **阶段 3：创作模式 LangGraph 工作流闭环**
   - 提纲规划、分章并发、Mermaid 架构图与 UI 截图生成、全文缝合。
4. **阶段 4：编辑模式与受控重写工作流**
   - Word 批注/外部意见解析、上下文依赖分析、局部定向修改、自动重排序号与 Diff 输出。
5. **阶段 5：用户交互界面与工程打磨**
   - 简洁的 Web/桌面交互界面，提供“一键生成”与“上传审改”的丝滑体验。
