# 职责、权限与产物契约

## 责任边界

| 角色 | 读 | 写 | 执行入口 |
|---|---|---|---|
| 大纲 | 题目、事实源 | 结构化大纲，程序校验提交 | 无工具 |
| 文献 | 检索需求、年份约束 | 核验题录，程序提交 | 固定文献检索 |
| 撰写 | 事实源、大纲、题录、已完成小节快照 | 小节 JSON，调度器保存 | read_section、code_asset |
| 编码 | 当前编码任务、自己目录、只读运行依赖 | 自己的独立编码目录 | 隔离 bash/read/write/edit |
| 模板准备 | 显式绑定的学校 DOCX | 单独 template 目录中的副本与清洗计划 | 固定 inspect/build/verify |
| 成稿装配 | 已批准模板、已验收正文与资产 | assembly 目录中的 DOCX 与校验报告 | 固定 inspect/assemble/verify |

`ROLE_TOOLS` 是不可变角色白名单。各角色的具体工具实例来自绑定上下文的工厂；外部 Skill 不得注入可执行工具。撰写的执行分派再次检查白名单。模板工具注册完成后关闭新增入口。装配 agent 无自由模型循环，固定执行三个动作。

编码委派按 `section_id + asset_id` 匹配当前大纲，只能生成当前小节预先声明的资产。每项任务新建 UUID 目录，失败任务不发布产物。父 agent 验收图片格式、表格结构、模板约束和普通文件属性后复制发布。撰写可以整理图题，但不可改变返回的资产类型或路径。提交时记录正文、源码和资产指纹，续跑与装配均重新核验。

## 编码隔离

Bubblewrap 使用独立用户、进程、网络等 namespace，移除 capability。仅挂载任务目录为持久可写，系统库与 Python 虚拟环境只读；`/tmp` 与 HOME 为隔离临时目录。清空继承环境，只传 PATH、LANG 等运行变量，不传 API Key。宿主 `/proc`、`/tmp`、项目和 `.env` 均不可见。

仅把 cwd 指向工作区不构成隔离，因此不允许回退到普通 shell。超时结束进程，PID namespace 回收后台后代。模型调用仍在宿主进行，编码子进程没有网络。Python 文件工具同时检查规范化路径和符号链接。

隔离面向当前 Linux 运行环境；模型客户端和受信任的调度代码不是攻击者提供的插件。允许自定义 Python 工具的通用历史基类不属于上述角色入口。

## 保留模板格式

准备与装配是两个阶段。准备阶段可根据学校明确要求清洗、重建样式；批准后通过 SHA256 固定模板。装配器只替换已声明的元信息、正文锚点和内容原型。

- styles、fontTable、theme、numbering 及其他非内容部件逐字节保留。
- 已有分节、页眉页脚格式保持；页眉中的题目可按绑定替换文本。
- 段落复制 pPr/rPr；表格继承表头、普通行、末行及列宽；图片显示尺寸来自原型，编码输出比例必须一致。
- 引用使用确定性书签名和原生 REF；图表编号使用 SEQ。引用缓存按装配顺序生成，Word 的动态更新 UI 需另行验证。
- 来源/图表不完整、模板指纹不符、缺少原型或正文被修改时拒绝产出，不退回默认模板。
- 确定性 ZIP + 重放对比验证重复装配字节一致。正文增长后的分页由排版引擎处理，视觉检查通过 PDF 派生物，不回写批准模板。

## 目录与测试迁移

实现统一放入 `src/agent`，按 security/coding/template/writing/assembly 分职责。根目录 `agent` 是兼容 import 入口；安装采用 pyproject 的 src 布局。

原 `test` 脚本已按中文问题迁入 `tests`，原 fixtures 进入模板提取目录，历史日志与渲染产物集中归档。根目录 `test` 仅保留旧模块导入兼容层。历史脚本不作为当前角色验收证据。

自动回归每次按问题目录保存 `runs/时间_问题/result.json`。Kimi 真实测试显式执行 `tests/Kimi真实编码与装配/run_real.py`，保存模型调用、用量、编码源码和产物、状态、装配报告。运行产物不进入 Git；测试代码、夹具生成器与规范纳入版本管理。
